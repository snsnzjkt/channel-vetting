# The workflow installs this with `pip install --require-hashes -r
# requirements.txt`, which refuses to install any artifact whose sha256 is
# not listed below. A hijacked PyPI account or a substituted mirror artifact
# then fails the install instead of running arbitrary code in a job that has
# AIRTABLE_TOKEN and YOUTUBE_API_KEY in env.

# CONSEQUENCE: adding or bumping ANY dependency means regenerating this
# whole file. pip fails the entire install if a single entry lacks a hash,
# and transitive dependencies count. Do not hand-edit a version number here.
#
# Regenerate with:
#
#   pip install uv
#   uv pip compile requirements.in --generate-hashes --universal \
#       --python-version 3.12 --no-annotate --no-header \
#       --output-file requirements.txt
#
# ...where requirements.in holds only the DIRECT dependencies:
#
#   requests==2.34.2
#   python-dotenv==1.2.2
#   playwright==1.62.0
#   playwright-stealth==2.0.3
#   pytest==8.3.3
#   tzdata==2026.3
#
# everything else below being transitive. `--universal` matters: an ordinary
# pip-compile / uv-pip-compile run resolves only for the platform you ran it
# on, and this file has to satisfy both ubuntu-latest CI and a Windows dev
# box (hence the `sys_platform == 'win32'` marker on colorama). Then verify
# BOTH targets before committing, e.g.
#
#   pip install --require-hashes --dry-run --ignore-installed -r requirements.txt
#   pip install --require-hashes --dry-run --target /tmp/t --only-binary=:all: \
#       --python-version 3.12 --implementation cp \
#       --platform manylinux_2_17_x86_64 --platform manylinux_2_28_x86_64 \
#       --platform manylinux_2_34_x86_64 --platform manylinux_2_39_x86_64 \
#       -r requirements.txt
#
# The resolution assumes Python >= 3.12 (the workflow pins 3.12). On 3.10 or
# 3.11 pytest additionally requires tomli and exceptiongroup, which are
# correctly absent here and would make the install fail on those versions.
#

#

# reset zone) and prospect_day.py does ZoneInfo(PROSPECT_DAY_TZ). zoneinfo
# falls back to the tzdata PyPI package only when there is no SYSTEM tz
# database - and Windows has none. Without this pin, importing
# quota_tracker on a Windows dev machine raises ZoneInfoNotFoundError and
# the whole pytest suite fails at collection. It looked optional purely
# because ubuntu-latest ships a system tzdb, so CI passed while local runs
# could not import the module at all. Pin it like every other dependency;
# do not move it to an extra or a "dev only" list.
